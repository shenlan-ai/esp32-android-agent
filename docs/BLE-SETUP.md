# 当前经典 ESP32 的 BLE 控制

BLE0.1.4新增通用path/circle连续笔划，支持一次按下经过多个点后释放，路径取消沿用紧急停止。新版和四板编译/软件回归见已归档变更`add-continuous-hid-strokes`；当前板已单次刷入0.1.4并读取校验，手机重连后键鼠订阅均就绪，并完成绑定0.1.4的531/1176竖屏校准、闭合多段path/circle及第二段中途停止释放实测。VLM案例另作独立验收。升级需先完整备份、明确覆盖确认并重新校准。模型点为完整画面0–1000，不能直接使用手机像素或浏览器CSS坐标；具体限制见[协议](../hardware/PROTOCOL.md)。

BLE 0.1.3的历史实测：修复非等比例斜向定位/拖动被分成斜线和轴向尾段的问题，保持50ms报告节奏和可中断调度。Redmi Note14 / Android15当时完成单次刷写和读取校验、重新连接及531/1176计数校准，四组实际拖动没有出现轴向尾段，中途停止收到手机释放；详细证据见实机记录。0.1.4不能沿用该校准。其他机型、精细定位和S3实物仍待验证。

当前连接板已识别为 ESP32-D0WD-V3 revision v3.1、4MB Flash，电脑串口 COM5。商品板名仍未知。CP2102只是串口桥；此芯片没有原生USB HID。

## 连接

```text
电脑 ── USB串口 ── 经典ESP32 ── BLE键鼠 ── 安卓手机
  └──────────────── USB或无线ADB ──────────┘
```

手机不需要安装伴侣App，板子不需要Wi-Fi。蓝牙只用于键鼠控制，ADB负责画面。

## 构建与保留原固件

普通用户可以使用 [Windows 便携包的网页向导](PORTABLE.md)：展开“ESP32 HID 控制 → 安装或更新开发板固件”，选择串口并识别，经典 ESP32 4MB 选择 `esp32dev`，完整备份并下载后确认覆盖、写入并校验。向导会重新核对同一板子的 MAC、芯片和容量；失败不自动重试。便携包提供刷写工具，无需用户安装 Python/Arduino。源码运行需要 `server[firmware]` 和 `--firmware-dir`，见开发说明。

贡献者在项目根执行（Windows虚拟环境）：

```text
uv pip install --python .venv/Scripts/python.exe platformio==6.1.19 pip==25.3
.venv/Scripts/python.exe -m platformio run -d hardware/ble_bridge
python scripts/identify_board.py --port COM5
python scripts/flash_board.py --port COM5
```

最后一条只备份4MB Flash到`.runtime-local/firmware-backups/`，不写固件。此备份包含原设备配置，保留在本机，不提交仓库或分享。脚本同时写SHA256；恢复可用esptool在地址0写回完整备份，恢复也会覆盖当前Flash，应明确确认。

当前固件PlatformIO目标`esp32dev`，espressif32 6.12.0 / Arduino ESP32 2.0.17、ArduinoJson 7.4.2；DIO、4MB、40MHz Flash、min_spiffs分区。未使用GPIO引脚、板载LED或PSRAM，因此不依赖DevKit特定PCB引脚。刷写前检测必须为经典ESP32和4MB，S3等芯片会被拒绝。

Arduino框架包固定为`3.20017.241212+sha.dcc1105b`，构建用esptool包固定为`2.40900.250804`。uv创建的虚拟环境默认没有pip，构建环境需安装pip供PlatformIO安装工具依赖；普通用户运行控制台不需要PlatformIO。固件协议见 [串口协议](../hardware/PROTOCOL.md)。拖动使用校准时相同的鼠标步幅与节奏，指定时长是按下的最低时长；实际执行时间由板子返回。BLE鼠标操作不提供精确触摸时序保证。

BLE0.1.1及0.1.2采用50ms运动报告和归位后600ms等待，优先验证落点稳定性；它比原10ms节奏更慢，具体延迟看实际`execution`。校准记录与握手固件绑定，升级后坐标能力会等待重新校准，旧计数不能直接沿用。原生USB固件仍使用10ms节奏。0.1.2已在当前Android15手机上命中三个目标并验证长动作及停止；精细落点仍有偏差，不将编译或调度器测试当作全机型通过。

用户明确决定替换原固件后执行：

```text
python scripts/flash_board.py --port COM5 --write --confirm-overwrite
```

脚本先验证构建产物、再创建完整备份，成功后才写bootloader、分区、OTA初始化和app；esptool校验写入数据。此命令会替换原固件，不是芯片识别。

刷写后关闭其他串口工具，在已安装服务端依赖的环境执行：

```text
.venv/Scripts/python.exe scripts/check_board_link.py --port COM5
```

该检查不发送点击、鼠标移动或键盘动作；验证协议握手、错误消息拒绝、停止回复、心跳看门狗、生产主机自动心跳及关闭重连。报告明确区分板上通信与手机输入验收。它会建立新会话并清理输入，应在没有运行任务时执行。

## 配对和校准

校准绑定真实握手中的有效固件版本。未知版本仍可使用键盘和无点击定位诊断，但不能保存或使用坐标校准；升级固件后请重新校准。

1. 板子留在电脑，手机在系统蓝牙设置配对`Android Agent BLE`。若换手机，先在原手机忘记设备。
2. 用USB或无线ADB连接手机，在控制台选择手机并确认画面。
3. 展开“ESP32蓝牙控制”，刷新串口，选板子并点击“使用BLE控制”。未刷入本项目固件会显示连接失败；不会自动改用ADB发送输入。
4. 配对后展开鼠标校准。如果系统允许，关闭指针加速。使用水平/垂直边缘测试（只移动不点击），调整计数到刚好触及对应边缘。过大的数值也会触边，所以应逐渐减小到临界值。
5. 保存当前方向校准，再点屏幕中心和边缘多个位置检查精度。边缘校准不是全屏精度证明；明显偏差时不要运行自动任务。
6. 测试点按、滑动、长按、ASCII输入和紧急停止。旋转或更换手机需重新校准。相同分辨率但指针速度设置变化也需重新校准。

主页、返回、最近任务暂不作为BLE特殊按键提供，因为普通键盘Home不等于Android主页。可点击手机屏幕导航控件。输入按美国键盘布局，中文需要后续可选输入法扩展。HID字母仍经过手机输入法，输入前需由用户切为英文，并检查标点是否为半角；中文模式可能将`agent`转换为汉字。项目目前不自动切换输入法。先在空的本机测试字段准确输入一次，避免在真实表单中试输或重复发送。

贡献者可显式运行`python scripts/phone_input_fixture.py`，按当前已授权手机执行`adb reverse tcp:8894 tcp:8894`，在手机浏览器打开`http://127.0.0.1:8894/`。该工具仅监听本机并保存有界输入事件，不连接ADB、板子或模型，不纳入正常工作台启动。检查结束后关闭工具并移除本次reverse映射；不得把预置或模拟事件当成真实输入。当前实际结果见 [Redmi Note14实机记录](acceptance/2026-10-13-redmi-note14-ble.md)。

## 状态边界

网页向导的完整Flash备份以115200波特率在同一连接中按256KB连续分段读取，每段保留esptool传输摘要校验，全部完成才生成完整备份和SHA256；4MB可能需要数分钟。读取期限按容量计算（最少600秒），8MB允许更长时间但仍有界。传统经典4MB脚本也采用115200及600秒，但仍调用CLI整片读取。等待时保持USB连接；失败不会自动提速、切速或重复读取，也不会开放刷写。写入继续使用460800和读取校验。本机CP2102高速和低速整片读取均已观察到失败；末尾256KB低速读取通过，但向导分段完整备份也在193.4秒失败，没有写Flash。以上为历史失败；更换主机USB口后一次完整4MB备份及下载SHA已通过。失败根因尚未确定，低速、分段或一次成功不代表长期可靠。

BLE0.1.2增加分层诊断提示。蓝牙链路已连接但未认证时，提示忘记设备后重新配对；已认证但键盘或鼠标报告未订阅时，提示重连并检查系统蓝牙设备详情中的键盘/鼠标选项（若系统提供）。普通页面不显示认证错误码，诊断不替代键鼠就绪检查，也不会自动重连或发送输入。旧固件继续使用原配对提示。此版本已在当前板子写入并读取校验通过。初次诊断为链路和认证成功、键盘/鼠标通知未订阅，系统当时拒绝输入；手机忘记设备重新配对后已就绪，当前校准及输入证据见末尾。升级后仍需重新校准。

2026-10-13用户更换可靠数据线并直连USB后，向导完整备份335.5秒失败，此前已完整成功3407872/4194304字节；没有完整备份或Flash写入。串口重新绑定成功，仍是0.1.1/hid_ready=false。更换线材未解决整片读取，部分读取成功不允许跳过完整备份要求；继续排查其他USB口及外接接线，根因尚未确定。

固件工具失败提示区分识别、临时读取程序启动、Flash读取、备份保存、写入和写后校验。读取进度只统计此前完整成功的段，不包含失败段；只读操作失败明确“未写入Flash”，写入或校验失败则保持结果不确定并要求保留完整备份。工具只传递固定故障类别和有界计数，原始异常和设备私密资料不进入网页。旧工具没有诊断字段时仍给出当前操作的通用提示；这些信息帮助排查，不证明USB线材已损坏或BLE已恢复。

## 0.1.2实际恢复与输入（历史）

手机忘记设备重新配对后，显式COM5重绑：link/authenticated/keyboard_subscribed/mouse_subscribed均true、hid_ready=true。实际两次Tab焦点后一次agent-test-123原文输入与截图/DOM一致，板上574ms。

无点击定位100/100在第二、第三次截图像素相同，350/600两次落点相同；450/900、250/450及回到100/100也已观察。当前竖屏校准514/1143计数。生产tap命中左上、中心、右下三个目标（实际鼠标down/up/click各一次）；耗时2786/4540/5409ms。Android相对鼠标仍有加速/落点偏差，不保证像素级小目标或全机型精度。

5000ms长按实际5010.3ms、1000ms长按实际1013ms，释放buttons=0；700ms滑动拖动紫色目标、实际按下819.5ms；scroll -3实际滚动0→112.35555 CSS px。早期事件观察脚本用performance.now最大值匹配了旧页面事件，不算中途停止证据；后改用事件数组索引观察新pointerdown。

备份/写入失败历史保留；新USB口本次完整4MB成功不证明原失败根因或长期可靠性。Android16/17、其他品牌、S3实物、旋转/拔线过程仍未验收。
