## Context

经典 ESP32 留在电脑，用串口/BLE；S3 插在手机，电脑通过局域网控制板子，截图须无线 ADB。当前只有经典 ESP32，S3 的实机验证明确待补。

## Goals / Non-Goals

实现可配置、可构建、可测试的 S3 路线；不覆盖当前板、不声称通用手机兼容、不提供 Android 特殊导航键映射。

## Decisions

1. S3 的 native USB 使用 TinyUSB HID 键盘/相对鼠标和 CDC，禁用 PSRAM 依赖，不使用外部 GPIO。板型分别固定 Flash 8MB/8MB/4MB；DevKitC-1 用 USB 口而非 UART 口。
2. 共享 BLE 的 action_engine.h / protocol_validation.h，JSON v1 命令、随机会话、动作编号去重、1500ms 看门狗不变。USB 用 usb_connected 表示 USB 主机枚举状态，不声称已识别手机。报告提交失败使结果未知；释放区分已发送和未确认。
3. NVS 保存单个配置 JSON，CDC 只允许 get_config/configure，不允许 HID 动作。网页先读取 S3 身份再写入 Wi-Fi(2.4GHz)、主机 IPv4、端口和每板随机密钥；保存成功后重连网络，不必编译。凭据不进入响应/日志，错误不包含串口原文。
4. 独立 TCP 服务默认关闭，用户点击启用或配网后持久启用，默认 0.0.0.0:8891，网页仍只本机。端口被占用只影响 USB 路线。接受连接先发送随机挑战，验证 HMAC-SHA256(key, android-agent-usb-v1:nonce:board_id)，常量时间比较；限制未认证连接数和握手时间。认证绑定一个板子，活跃连接不被新连接替换。局域网 TCP 没有 TLS，使用可信局域网；不发送模型密钥或手机截图给板子。
5. listener 持有当前连接并维护心跳；断线后板子可重新认证，但当前控制器持有旧会话，必须显式重新绑定。取消/超时不重放。关闭连接或 USB/Wi-Fi 失效立即清空动作并释放输入，看门狗作为兜底。网络连接尝试只在没有动作时进行并限制超时。
6. 主机复用 HID 坐标转换和串行执行，USB 单独保存按 board_id + phone 的校准；切换必须确认插入当前手机，并验证 ADB transport=wireless。页面提供配网、监听状态、绑定和共用校准入口，英文/中文一致。
7. 监听启停和配网共用管理锁，设备操作继续使用会话锁；IO 完成后从最新设置生成保存快照，避免同时保存模型配置时覆盖新值。浏览器请求取消时有界物理配置写入仍完成并持久保存相应主机凭据。

## Risks / Trade-offs

相对鼠标加速因机型而异，必须校准和实机验证。USB 枚举不能证明手机身份，必须人为确认。无 S3 实物，本变更只验收构建、真实调度和模拟 TCP/CDC；手机 HID 和物理断线释放留在总体实机验收。配网必须已刷本项目 S3 固件；发布固件/刷写打包另立变更。

## Validation

构建三个目标；原生 g++ 运行共享动作代码；真实 loopback TCP 模拟认证、会话、心跳、取消、超时、断线和显式重连；模拟 CDC 检查身份、长度、秘密和失败行为；API 验证 mode/无线约束/生命周期；提供明确 DEMO 的离线 S3 配网 fixture，浏览器验证表单、绑定、校准及状态。fixture 仅本机端口，禁止实际串口和模型调用。记录所有未执行实机检查。
