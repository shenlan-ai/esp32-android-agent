## Context
当前手机已授权连接，旧笑脸已保存。工作台重启后为 ADB 模式；演示前明确恢复已配置 BLE 控制和已有校准，确认实际能力。

## Decisions
- 录制新的演示笔记，保持原有笔记。每次输入必须来自新 MCP 观察，结果不确定先重新观察，结束调用 android_stop。
- 当前调试连接标识若变化，先用只读机型/系统信息及画面确认是同一 Redmi，再通过校准接口将既有 1080×2400、BLE0.1.4、531/1176 校准绑定到当前连接，观察实际定位效果；不跳过有效性保护。仅本机偏好文件改变，不提交设备信息。
- 原生 screenrecord 采集手机实际画面，ADB 不用于输入。录制起点为空白绘图画布，避免展示笔记列表、个人内容、主机密钥或设备地址。
- 最终媒体选取本次保存并重新打开的笑脸；只裁切/等比缩放去除状态栏，不能重画或替换笔画。若需要剪去等待，必须公开处理，不伪装原速度；优先连续原速视频。
- MP4 使用 H.264/yuv420p/faststart，适合浏览器播放；GitHub README 使用可见预览图链接到仓库 MP4，并提供下载/播放链接，不依赖被过滤的 video 标签。不引入运行依赖。
- 英文 README 保持默认，中文同步；新案例放到显眼位置，旧白板与 hello 验收保留为有边界的历史链接。
- 本机录制/处理临时脚本与私人原始记录保留在忽略目录，公开媒体只含授权的演示笔记；最终记录核验视频可解码、首中尾画面、最终图像及文档链接。

## Validation
先严格校验本变更；实机 MCP 核验 BLE 就绪、绘图、保存、重新打开及输入释放。检查媒体编码/尺寸/时长/大小及实际抽帧；检查本地 Markdown 链接、中英文对应、差异空白、OpenSpec 正式与归档校验及范围。文档媒体变更不新增镜像实现测试，复用此前 MCP 回归并准确引用。
