## Decisions
- 首屏重新截取8890当前源码控制台的桌面工作区：真实手机预览显示常规桌面/系统画面，导航、任务面板和紧急停止可见；精确记录视口和截图来源，仅遮盖设备连接标识，不以旧DEMO代替新实机前端图。
- GitHub会过滤普通HTML video，必须通过仓库编辑器上传已授权的公开演示MP4取得GitHub附件URL，在README独立行直接嵌入并实际验证播放器；仓库MP4作为可下载回退，不以有标签但不显示的播放器声称完成。若上传不可用，则记录实际阻塞，不伪造附件URL。
- 闹钟录制在恢复到常规桌面后开始，MCP负责打开Clock、设置明天07:30的一次性闹钟及确认保存；录屏/文件拉取及只读信息使用ADB，不发送ADB手机输入。使用所选控制器已声明能力，若需要改变模式必须明确配置；不得用未声明的home动作。保留旧闹钟，最终明确报告新闹钟时间和开启状态，录像不验证实际响铃。
- 每个 MCP 输入都遵守 status → screenshot → one action → screenshot；若页面未切换则继续观察而不重复输入。结束调用 `android_stop`，并用新的截图确认闹钟列表。
- 闹钟演示媒体只包含 Clock 页面和常规系统画面，不展示笔记、账号、密钥或设备标识。截图保持常规前端/手机画面要求，README 不再插入手机效果静态图。
- 原生录屏达到180秒上限，第一段实际175.47秒只记录至07:30设置页、保存发生在上限之后。追加真实MCP重新打开核验及原值保存片段，按原速拼接并明确披露两段录制及中间间隔；不得称为连续完整创建录像。更新公开媒体及GitHub附件，核验最后一帧含开启的闹钟列表。

## Validation
严格校验变更；实机检查 BLE readiness、MCP 动作结果、闹钟开关和保存状态、输入释放。对两个 MP4 检查 H.264/yuv420p、时长、fast-start、完整解码、首中尾抽帧和 SHA256；检查 README 内嵌 video、回退链接、英文默认、中英文对应、本地链接与范围。复用此前 MCP/Python 测试，不伪造全机型兼容。
