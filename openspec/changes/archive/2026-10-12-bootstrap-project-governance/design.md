# Design

## Context

参考项目检出独立存在，当前目录未初始化 Git。整体架构已在讨论中确定，见 docs/ARCHITECTURE.zh-CN.md。使用已安装的 OpenSpec 1.13.1，以仓库本地 spec-driven schema 管理。

## Goals / Non-Goals

**Goals:** 规则可自动发现，规格格式可校验，修改文件可关联变更，后续开发无需额外授权即可按用户已确认范围推进。

**Non-Goals:** 本变更不实现运行时控制；不设置人为的重复审批关卡；不添加通用插件平台。

## Decisions

- AGENTS.md 为唯一规则源，agent.md 作为入口。标准文件名提高工具兼容性，入口满足用户请求。
- 每个变更使用 files.txt 声明实现文件范围，OpenSpec 元数据自身归属其变更。相比仅靠提交信息，可在工作树和 CI 自动检查遗漏。
- 范围检查仅采纳活动变更和对比基线后新归档的变更；既有历史变更不能授权新的实现修改。OpenSpec 自身负责格式校验，范围脚本不重写其解析器。
- 初始化 Git 并忽略参考检出、虚拟环境、密钥、设备配置和运行记录，保留上游许可证声明。
- 产品规格是后续能力的约束，当前可用状态单独记录，避免规格基线被误认为已实现功能。

## Risks / Trade-offs

- 手工范围清单需要维护 → 校验失败时补充清单并确认任务范围，不允许用根目录通配符绕过。
- 无实机时无法完成硬件验收 → 记录未执行项目，分开模拟、编译与实机证据。
- OpenSpec 版本行为变化 → 文档指定已验证版本并在更新工具前验证现有规格。
