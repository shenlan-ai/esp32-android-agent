# Design

## Context

Windows11 COM5 实测经典 ESP32-D0WD-V3 v3.1、4MB Flash。CP2102 驱动已恢复。串口只连接电脑，板子蓝牙连接手机，ADB 连接电脑和手机，因此不需要板子 Wi-Fi。

## Goals / Non-Goals

**Goals:** 提供当前芯片可用的固件构建、可停止串口 BLE 控制和用户可配置坐标校准。

**Non-Goals:** 不推测 PCB 商品名；不承诺尚未测试手机的鼠标加速度或安卓特殊导航键；不在此变更实现 S3 网络协议。

## Decisions

- PlatformIO 固定 espressif32 平台与 ArduinoJson；BLEHIDDevice 使用 Arduino ESP32 内置实现，鼠标和键盘独立 report ID，英文设备名 `Android Agent BLE`。
- 串口115200，JSON行最大1024字节。hello 建立新会话并释放输入；编号在会话内单调增长，只允许一个动作。重复编号返回已记录结果或执行中状态，不重放。协议版本不匹配拒绝执行。
- 串口物理连接无需 LAN 令牌；会话随机ID用于拒绝重连前旧命令。heartbeat 每500ms；失效1500ms或BLE断线时清空动作、释放输入并作废会话。仅手机蓝牙配对可以启用BLE控制。
- 主机单一读循环，命令 future 按编号关联；每个命令仅发送一次，超时标为结果未知。stop可在长动作期间发送，等待释放确认；读循环使用有限超时，取消和关闭不能无限阻塞。
- 固件动作按短周期执行，不使用阻塞长延时。鼠标先归位再按照固定报告速度移动，校准保存完整截图尺寸及到达右/下边缘所需的相对计数；尺寸变化后拒绝坐标动作。未校准时仅提供原始移动和键盘，绝不默认猜测坐标。
- Android 特殊 home/back/recents/volume 不作为此版本BLE能力；通过屏幕界面点按完成。ASCII键盘、Enter等基础键、tap/swipe/long_press/scroll/wait作为能力，逐项需用户实测。
- 浏览器显式切换 ADB 或 BLE。切换/选手机/停止通过同一设备会话锁；更换手机必须重新绑定板子与校准，断线不回落到ADB。
- 保留原固件备份到忽略目录，SHA256记录本机；覆盖刷写只在用户明确确认后进行，不把旧固件覆盖作为识别步骤。
- 将实际固件的动作调度抽成不依赖Arduino的模板函数，使用原生g++和假HID输出验证归位、按下、移动、字符释放及停止。原生测试复用固件执行代码，不以Python模拟重复实现。
- 拖动与校准移动使用相同10ms报告节奏，防止改变速度破坏相对计数校准。duration_ms是按键保持的最低时长，移动完成不足该时长时在终点保持后释放；路程所需时长更长时以实际移动时长为准。终端响应记录实际板上执行与按下时长，主机向调用者展示，不承诺精确触摸时序。
- BLE就绪要求加密配对且键盘/鼠标报告已订阅。监听库的通知结果，GATT提交失败或订阅失效不能返回done；停止仍清理板上状态，手机释放未确认时准确报告。
- 本地页面和静态资源不长期缓存；入口按文件修改时间标记主脚本和样式版本，避免更新后的校准/能力逻辑仍使用旧脚本。源码用户无需前端构建步骤。

## Risks / Trade-offs

- 鼠标加速度与厂商蓝牙实现不同：固定步幅/节奏、可配置校准及实机验收；不能靠理论宣称全部机型。
- USB串口复位：连接建立前等待启动，DTR/RTS不主动持续拉低；握手必须重新建立会话。
- 主机消失无法收到stop：固件心跳看门狗释放；手机断线仅能清理板子状态，不声称手机已接收释放包。
- BLE配对时持久bond：采用系统BLE配对，手机必须主动选定设备；若换手机先在原手机忘记设备。
